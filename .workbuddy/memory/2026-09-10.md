# 2026-09-10 工作日志

## 账户模块 profile 按钮/输入框样式修复（phone + 两个密码模块）
- 用户反馈：账号模块 profile 下的按钮和输入框样式有问题，特别是 phone 字段和 Login password / Payment password 模块。
- **根因（实测浏览器计算样式得出，非猜测）**：
  1. `.profile-form` 与 kit 的 `.ek-form` 同用，而 `elken-ui.css` 的 `.ek-form` 是 `grid-template-columns: repeat(2, minmax(0,1fr))`；`account-ui.css` 的 `.profile-form` 只设了 `display:grid; gap`，**没有重置 grid-template-columns** → 表单的 `.row` 被塞进半宽列。密码模块实测 `pwdForm` 为 `245px 245px`，三个密码字段挤在 245px 内、Save 按钮跑到字段**右侧**（而非下方）；个人信息卡同理（row 各 579px 并排）。
  2. `.phone-input-wrap` / `.phone-dial` / `.phone-number` 由 `ProductCatalog.phoneFieldHTML()` 动态生成，**全站 CSS 无任何样式** → 区号 select（`.ek-select` width:100%）与号码 input 各占满宽、上下堆叠（实测 413×45 + 413×48，stacked=true）。
  3. 密码模块在 `.ek-card profile-card` 内又套了一层 `.sec-block`（account-ui 的共享卡片类：白底+1px 边框+14px 圆角+24px padding+24px margin-bottom）→ 卡片套卡片。
- **修复（全部改 `assets/css/account-ui.css`，遵守"账户模块样式只动这一个文件"的约定）**：
  - `.profile-form { grid-template-columns: minmax(0,1fr) }` 强制单列；`.profile-form .row` 的 `margin-bottom` 改为 0（由父级 gap 统一间距）；加 `.profile-form > * { min-width: 0 }`。
  - phone：`.phone-input-wrap` flex + `max-width: 420px`；`.phone-dial` 固定 140px（右侧圆角 0）；`.phone-number` flex:1、`margin-left:-1px`（左侧圆角 0）拼成组合控件；focus 时 `z-index:1` 保证边框完整。
  - `.profile-card > .sec-block` 压平（透明底/无边框/无阴影/0 padding/0 margin）。
  - `.profile-form .row.cols-3` 的 minmax 由 180px 降到 150px，使 Current/New/Confirm 在半宽密码卡（556px）内排成 3 列（实测 174.6px×3）。
  - `.profile-actions .ek-btn { min-width: 132px }`；顺手修掉按钮 padding 里引用不存在令牌 `--ek-pad-x` 的写法。
- 验证（puppeteer 种入 `al.auth.user` + 点 profile tab + 进入 edit 模式）：桌面端密码三栏 174.6px×3、actions 在下方；phone 140+281 并排不堆叠；按钮 Cancel(白)/Save(深蓝) 各 132px；Member ID 仍 `disabled` 且带 `.input-locked`（未破坏硬规则）；移动端 ≤767 按钮满宽 316px、字段单列、phone 140+177 并排；0 page error。
- 合规：account-ui.css 改动前后均为 0 hex / 0 px 字号 / 0 `!important` / 括号平衡，新增行未引用未定义 token。
- 提交：`56d6a4b`。
- **经验**：`.ek-form` 是两列网格——任何页面给表单加 `.ek-form` 又想自定义 `.row` 布局时，必须显式重置 `grid-template-columns`（login.css 的 `.auth-form`、本次 `.profile-form` 都是这个坑）。

## 密码模块 Confirm 标签换行导致输入框不对齐的修复
- 用户反馈（附截图）：Login password / Payment password 里 "Confirm new password" 换行导致三栏输入框不对齐。
- 实测：列宽 175px，"CONFIRM NEW PASSWORD" 12px 大写 + 0.6px 字距需 179px（字距降到 0 也要 174px，仅 1px 余量）→ 换行不可避免；换行使第三个输入框顶部比前两个低 19px（1028/1028/1047）。
- 修复：`.profile-form .row.cols-3 { align-items: end }` 底部对齐——标签向上伸展，三个输入框保持同一水平线（实测 1047/1047/1047）。**只作用于 .cols-3**：个人信息行的 Member ID 字段下方有 hint，必须保持顶部对齐，不能用 end。
- 提交：`3608a4c`。account-ui.css 仍 0 hex / 0 px 字号 / 0 !important。

## Notification preferences 模块补齐样式
- 用户反馈：Notification preferences 布局和样式有问题。
- 根因：`.prefs-grid` / `.prefs-section` / `.prefs-section-head` / `.prefs-channels-list` / `.pref-toggle-card` / `.pref-toggle-info` / `.ch-title` / `.ch-desc` / `.custom-switch` **全部在全站 CSS 中零定义**（与之前 phone 字段同类问题）；只有 `.prefs-form` 存在于已弃用的 `pages.css`（旧 `--ink`，无页面链接）。
- 修复前实测：卡片 `display:inline`、原生复选框裸露 13×13、`.custom-switch` 为 0×19 空白 span（完全没有开关 UI）、标题与描述同为 15px/400 无层级。
- 修复（`account-ui.css` 新增 16b 节）：
  - `.prefs-form`/`.prefs-grid`/`.prefs-section` 结构；`.prefs-section-head` 蓝色 h3 + 分隔线 + 灰色描述。
  - 渠道卡片：surface+border+`--ek-radius-lg`、hover 加深边框、`:has(input:focus-visible)` 焦点环；`.ch-title` 13/700、`.ch-desc` caption 灰色。
  - 自定义开关：44×24 pill 轨道 + 18px 滑动圆钮（`::after`），原生 checkbox 仅视觉隐藏（保留 a11y）；选中态轨道变品牌蓝、圆钮 translateX(20px)、卡片 `--ek-info-tint` 底 + 蓝边框。≤600px 收紧内边距。
- 验证：桌面/移动端卡片 flex 圆角 14、复选框隐藏、开关 44×24；关闭态=灰轨道+圆钮 0，开启态=蓝轨道+圆钮 20px+浅蓝卡片；0 page error。

- 功能未动：`app.js` 的 `getPrefs` 默认 email/sms/wa 全开，Save 已在 account.html:2361 绑定。
